## 1. Governance & Categorization Standard

Every independent review finding is classified into one of three explicit statuses:
- **`RESOLVED`**: Fully implemented, tested, and validated within approved scope with concrete test evidence and Git commit citations.
- **`SPECIFIED / DEFERRED (<Phase X>)`**: Architectural contracts, DDL schemas, security invariants, and failure boundaries are strictly specified and locked in documentation and typing contracts, while physical runtime execution logic is deferred to the named roadmap development phase. Documented designs are not falsely labeled as implemented runtime functionality.
- **`OPEN`**: Unresolved finding requiring active remediation or runtime implementation in a designated future phase. Passing tests are NOT cited as evidence for unexercised runtime features.

  1. *SQLite WAL Durability:* Configured with `PRAGMA journal_mode = WAL;`, `PRAGMA synchronous = NORMAL;`, `PRAGMA foreign_keys = ON;`, `PRAGMA secure_delete = ON;`, and `PRAGMA busy_timeout = 5000;`. Explicit `BEGIN IMMEDIATE` transaction blocks prevent deadlocks under high multi-process contention.
  2. *Atomic 4-Phase Step Commit Protocol:* Guarantees transactional atomicity across step execution: `INTENT_RECORDED` $\rightarrow$ `TOOL_DISPATCH` $\rightarrow$ `OUTCOME_UPDATE` $\rightarrow$ `ATOMIC_STEP_COMMIT`. Step outcomes, token usage, memories, checkpoints, and trace events are committed in a single atomic SQLite transaction.
  3. *ID-Based Tombstone Reconciliation Safeguard:* Checkpoint rehydration queries active tombstones and strips known tombstoned memory IDs from restored working memory and candidate pools before execution resumes. *Limitations:* Because reconciliation is strictly ID-based, it does not provide universal anti-resurrection guarantees for memory content already embedded in serialized prompts, step history, tool outputs, or derived memories created under new IDs prior to erasure.
  4. *Orphaned Run Detection & Dirty Rollback:* Process crashes leaving runs in `RUNNING` or `PAUSED` are detected and reconciled to `FAILED`. If mutating or non-idempotent tools were dispatched, the run is explicitly flagged with `error_code="PARTIAL_DIRTY_ROLLBACK"` and `is_dirty=True`.
  5. *Tool Idempotency & Execution Guarantees (P2-H1):* Separates runtime invocation identity (`invocation_id`) from caller-supplied `business_operation_id` and verifies canonical argument fingerprints. Trusted `business_operation_id` values (and tools with `supports_provider_idempotency=True`) provide durable deduplication under implemented constraints; operations without trusted IDs have best-effort duplicate suppression within the same run. Exactly-once external execution is not universally guaranteed; uncertain non-idempotent writes without verified provider idempotency are blocked with `OUTCOME_UNKNOWN` and `PARTIAL_DIRTY_ROLLBACK`.
  6. *Pre-Persistence Security Boundary (P2-H2):* `PrePersistenceValidator` protects all durable tables (`runs`, `run_steps`, `memory_records`, `tool_invocations`, `trace_events`, `checkpoints`) and database/WAL bytes. Performs pattern-based in-place credential redaction by default (`fail_closed=False`), with opt-in fail-closed write rejection (`fail_closed=True`), and fails closed across all modes when structural sanitization fails.
  7. *Checkpoint Lineage Isolation (P2-H3):* Per-run checkpoint lineage tracking on `LifecycleState` and storage boundary parent validation prevent multi-tenant and sequential run contamination.
  8. *Multi-Signal Scored Memory Retrieval:* Scored retrieval combines relevance (tokenized OR matching), recency (exponential half-life decay), salience, and confidence over a bounded pre-limit candidate pool (`P2-LOW1`).
  9. *Deterministic State Hashing:* Checkpoints and trace events employ deterministic unkeyed SHA-256 state hashing for divergence detection.
