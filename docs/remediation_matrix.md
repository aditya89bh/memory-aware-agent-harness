## 1. Governance & Categorization Standard

Every independent review finding is classified into one of three explicit statuses:
- **`RESOLVED`**: Fully implemented, tested, and validated within Phase 0 scope with concrete test evidence and Git commit citations.
- **`SPECIFIED / DEFERRED (<Phase X>)`**: Architectural contracts, DDL schemas, security invariants, and failure boundaries are strictly specified and locked in Phase 0 documentation and typing contracts, while physical runtime execution logic is deferred to the named roadmap development phase. Documented designs are not falsely labeled as implemented runtime functionality.
- **`OPEN`**: Unresolved finding requiring active remediation before Phase 0 lock. (Currently: **None**).

## 4. Residual Architectural Findings Matrix (R-1 through R-4)

| Finding ID | Title & Summary | Status / Category | Remediation Details & Architectural Clarification | Commits | Technical Limitations & Future Phase Scope |
|---|---|:---:|---|:---:|---|
| **R-1** | **Cryptographic Namespace Verification & Tamper Detection Claims**<br>Previous docs claimed cryptographic namespace isolation and tamper-proof state hashing. | **SPECIFIED / DEFERRED (Phase 7 & Phase 12)** | Clarified in `SPEC.md`, `ARCHITECTURE.md`, and `docs/security.md` that SHA-256 state hashing provides deterministic execution verification and replay divergence detection, NOT authenticated tamper-proofing against an active adversary with direct database write access. Namespace isolation is enforced via strict relational query parametrization (`WHERE namespace_id = ?`), not cryptographic zero-knowledge proofs. | `7e7457d`, `4577952` | Authenticated tamper detection via HMAC / digitally signed event digests deferred to telemetry hardening (Phase 7) and security audit (Phase 12). |
| **R-2** | **Erasure Scope Across Multi-Tier Boundaries & Flash Media Realities**<br>Erasure guarantees did not specify all storage tiers and made unrealistic claims about SSD hardware wiping. | **SPECIFIED / DEFERRED (Phase 4)** | Specified multi-boundary erasure obligations covering: active memory store, derived memories (`origin_status = 'ORIGIN_PURGED'`), working memory context caches, checkpoint snapshots, event traces, and telemetry exports. Acknowledged that POSIX file deletion, SQLite `secure_delete=ON`, and `PRAGMA wal_checkpoint(TRUNCATE)` zero database pages and truncate WAL frames, but SSD Flash Translation Layers (FTL) wear-leveling prevents POSIX guarantees of physical silicon cell erasure without cryptographic erasure or full-disk encryption. | `7e7457d`, `4577952` | Active cascading purge engine across all tiers deferred to Phase 4. |
| **R-3** | **SQLite Durability Trade-offs with `synchronous=NORMAL`**<br>Unqualified ACID durability claims in SQLite WAL mode. | **SPECIFIED / DEFERRED (Phase 2)** | Clarified durability trade-off in `SPEC.md`, `ARCHITECTURE.md`, and ADR-0003: SQLite WAL mode with `PRAGMA synchronous=NORMAL` is completely crash-safe against process/application termination and offers superior write throughput, but in the rare event of an OS kernel crash or sudden host power loss, recently committed transactions not yet synced to disk may be lost (though the database remains structurally consistent without corruption). Full power-loss durability (`synchronous=FULL` or `EXTRA`) is available as a configurable option. | `4577952` | Physical storage engine configuration and benchmark suite deferred to Phase 2. |
| **R-4** | **Orphaned-Run Recovery & External Tool Side Effects**<br>Orphaned-run recovery claimed automatic recovery of interrupted tool executions. | **SPECIFIED / DEFERRED (Phase 1 & Phase 5)** | Clarified in `SPEC.md`, `ARCHITECTURE.md`, and `contracts.py` that when an orphaned run left in `RUNNING` on host termination is rehydrated, in-flight tool invocations with unconfirmed outcomes transition to `OUTCOME_UNKNOWN`. The agent harness cannot unilaterally assume success or failure for non-idempotent external calls; human operator intervention or compensating actions are required. | `5a85a4d`, `4577952`, `12d05b6` | Runtime recovery loop deferred to Phase 1; sandboxed tool dispatcher deferred to Phase 5. |
